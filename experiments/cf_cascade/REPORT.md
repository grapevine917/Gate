# 原始MLP / CF风险二次剪枝 / 原分数二次剪枝：严格同Recall对照

## 设置

冻结已有原始17维MLP和反事实双输出模型，不重新训练。SIFT1M，沿用上一实验互斥的500/250/250查询划分，仅在原验证及测试各250条上评估。L100、beam4、K10、4线程、10000节点静态BFS缓存。原DiskANN源码和原模型不修改，独立库只加入Keep后的二阶段分支。

二阶段第一阶段阈值固定为生成E4-1标签时的原始阈值 0.024352464824914932，缓存命中始终保护。

三组：

1. **MLP**：原分数 `p<tau`，63个单阶段阈值。
2. **CF cascade**：先原MLP；只在cache-miss且原MLP Keep时调用CF，若 `risk<rho` 再Skip；57个risk阈值，不使用收益门槛。CF输入仍只有相同17维状态。
3. **Score cascade**：先原MLP；只在Keep时用同一次推理的原分数判断 `p<tau2`；63个二次阈值，不重复推理。

Score cascade 数学上等价于单阶段阈值 `max(tau1,tau2)`，它控制了“二次剪枝只是更激进”这一解释。实际动态搜索中已逐阈值核验最终ID、Recall、请求和展开计数完全一致。

## 相同Recall的定义与评价范围

预先声明全网格，再分别运行完整验证/测试曲线。主比较只使用三组在同一250条测试查询上**最终GT命中总数严格相等**的工作点；Recall=命中数/2500，不用小数四舍五入相等、不用相同阈值，也不用相同验证Recall下限替代。每个精确命中数处，分别取本组网格中SSD请求最少的配置。

这是在固定评估集上建立实测同Recall曲线的描述性对照：利用测试曲线命中数进行工作点匹配并在点内选低成本配置，因此不是完全独立的部署参数选择。两个模型权重及网格均在测试之前冻结；未按测试训练或修改模型。验证集精确匹配后冻结的配置及其测试结果另存 `validation_locked_test_results.csv`，没有将其不同测试Recall冒充相同。没有使用插值结果、决策随机混合或逐query配额。

## 结果解读

共找到5个三组精确相同Recall的实测工作点，其中5个CF实际发生二次Skip；CF在4个点的SSD请求少于原MLP。完整工作点全部列出，未只挑有利点。
CF相对原MLP的请求变化范围为-12.25%至+0.04%。这只说明当前冻结模型和有限网格下的实测曲线，不能据单个点宣称普遍优胜或在未观察查询上保持同样Recall。

原分数二次剪枝没有新的节点风险信息；其策略等价性已由全网格动态路径检验。CF二次策略若节省请求，则需以本表的同Recall成本差判断，不能由风险AUC提高、相同阈值或相同验证Recall下限推导。

Keep-only门控改善了反事实模型在原Skip节点上无标签却被调用的问题，但二次Skip仍会改变后续轨迹，不能把单节点收益标签相加为联合收益。原E4查询池此前已被多次观察；这些结果属于探索性对照。SSD是提交的请求数。LinuxAlignedFileReader使用O_DIRECT，绕过OS页缓存；每配置先预热同一查询集，但这不等同OS页缓存命中，也不代表冷设备性能。

## 核验与复现

验证和测试各63个原分数二阶段配置，均与对应单阶段有效阈值的最终ID和请求/展开计数一致。原E4固定阈值与既有E1程序最终ID一致。每个query原生断言二次调用数恰好等于第一阶段Keep的非缓存节点数、第一和第二阶段Skip和等于实际Skip总数。所有Recall独立从保存ID与GT重算；选定同Recall配置三轮ID及计数一致，原始源码及模型哈希未变。

复现：`bash experiments/cf_cascade/run.sh`。已有完整曲线结果会在输入锁一致时复用。
