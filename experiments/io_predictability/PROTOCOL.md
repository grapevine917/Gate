# 标签可预测性与在线策略实验

目标标签为 Cache Miss 节点的单节点跳过重放同时满足：逐查询 Recall@10 不低于原始搜索，且 Submitted SSD Read Requests 严格减少。原始搜索为既有 DiskANN 索引，L=100、k=10、beam=4、固定 BFS 缓存 10,000 节点，展开预算不设硬上限，禁用 ET/reorder。

查询划分沿用原实验的 query-disjoint train/validation/test。各数据集从原 8,000 条训练查询中用 seed=20261014 随机抽取 1,000 条；验证和测试均使用原 1,000 条。训练、验证新生成完整单节点反事实标签；测试复用 io_opportunity 的已有单节点标签。模型、标准化、类别权重仅拟合训练数据；标签阈值、策略选择仅使用验证数据。节点可跨查询重复，统计单位是查询—节点展开事件，不是 node-disjoint 泛化。

## 输入特征与读取边界

17 个状态：候选 PQ 距离、候选队列最佳/最差 PQ 距离、未展开候选在全队列中的排名、队列大小、未展开数量、已发现节点数、已完成展开数、此前 I/O beam 轮数、当前 beam 内位置、固定缓存驻留位、此前已展开节点的最佳 exact 距离、是否已有 exact 结果、候选/最佳 PQ 比值、候选/最差 PQ 比值、L、beam。部分字段为固定常数，训练标准化将其尺度置 1。

最佳/最差 PQ 边界来自 L 容量候选队列，不冒称 exact top-k 距离边界。best_exact_so_far 来自过去已完成展开，不是当前节点读取后才能得到的 exact 距离。缓存位通过内存缓存表查询。候选 PQ 距离来自既有驻内存 PQ 编码和候选队列。完整查询向量本身驻内存，作为第三个对照模型输入。

未使用当前节点完整向量、exact 距离、完整邻接表、邻居数、fresh/admitted 数、final-top-k 标记、反事实结果、GT、节点 ID 数值等作为模型输入。图入度/度数和节点历史收益不在本轮加入；这避免将 SSD 读取后得到的数据或测试反馈伪装成免费特征。标签文件的这些后验字段只用来定义目标与评价。

状态提取使用现有 SSD 读取前的 online_audit，冻结旧模型阈值为 0 以保证不剪枝，其 score 不作为特征。按 (query,node) 将 pre-I/O 状态与反事实标签连接并校验缓存状态和唯一键；不能按缓存命中与 miss 的最终处理顺序粗暴对齐。

状态获取有计算开销：例如候选排名/未展开计数需要扫描当前内存候选队列，不能称作零成本。模型与状态提取的在线成本包含在原生查询耗时中；模型加载/缓存构建不在查询请求分母内。

## 分类器与冻结阈值

固定超参数：StandardScaler + balanced LogisticRegression(C=1,max_iter=1000)，状态模型；balanced DecisionTree(max_depth=4,min_samples_leaf=200)，状态模型；同参数逻辑回归使用状态与完整查询向量。没有在测试数据上调参。报告 ROC-AUC、PR-AUC/AP（常数分数基线为正例比例）、balanced accuracy、precision、目标召回、质量关键误剪数和替代读取误剪数。

对验证集的非目标类别（质量关键 + 安全但请求不减少）设 0.1%、0.5%、1% false-positive rate 预算，用导出 float32 模型的 retain 分数选阈值；原生执行 retain_score < threshold 时跳过，缓存命中候选始终保留。小树的离散叶分数可能导致严格预算下无法跳过任何节点。线性概率仅为分类分数，不声称已经概率校准。

## 动态在线验证与测试

分类预测不等于联合安全。原生模型在每次候选展开前用当前路径状态重新评分，跳过消耗原 beam 槽位；不使用测试基线路径上预计算的掩码。完整验证搜索实际测量策略质量和净请求数，再在预先设定的平均 Recall 损失预算 0 / 0.1 percentage point 下，在三档阈值中选净请求最少者，若无可行策略则回退 baseline。零平均损失不等于逐查询不下降；报告受损查询数和严格结果一致率。测试评估全部冻结阈值用于诊断，主选择保持由验证集确定，不能从测试结果挑最好者。

Submitted SSD Read Requests 是 O_DIRECT Reader 提交的读取请求，不是 Physical SSD I/O。线上净节省用完整搜索请求差值；不能把安全单节点标签的收益相加。早先约七成的事后联合 Oracle 净节省是一项不同的条件性机会估计，不是分类器保证可达到的收益。PR-AUC 只验证 baseline 轨迹中单节点标签的可预测性；在线策略会改变轨迹，必须以实际查询 Recall 和请求数判断。
