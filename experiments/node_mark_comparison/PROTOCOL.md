# 非学习式节点标记 vs 17维状态LR

问题：跨查询积累的节点低贡献记录，能否以更低开销替代逐候选状态分类？标记方法不拟合分类器，无GT输入，只统计过去展开后的可观测贡献。

固定索引、K=10、L=100、beam=4、4线程、BFS cache=10000，禁止ET/reorder。SIFT1M与DEEP1M独立；直接沿用io_predictability的互斥train/validation/test各1000 queries。训练仅使用train/collected_candidates.csv中原始未剪枝轨迹的cache miss事件；不使用反事实安全标签、不使用验证或测试节点表现生成标记。节点ID可跨查询复用，这是被检验的假设。测试划分此前被其他实验报告过，并非首次观测的新测试集。

低贡献事件定义：该次展开没有邻居进入候选队列（admitted=0），且该节点不在该查询最终top10中（in_result=0）。这两个字段在原始查询完成后可观测，不需GT。即使符合此条件，仍不保证对其他查询安全。

每节点累计miss访问次数n与低贡献次数z。固定规则：n>=m且z/n>=r则标记。预先设m∈{1,2,5,10}、r∈{0.8,0.95,1.0}，共12组；m=1,r=1覆盖一次低贡献即记忆的朴素方案。n=0从不标记。训练阶段查询全部正常完成，不让标记改变训练轨迹；这是先积累记录、冻结后评估的版本，不冒称连续自适应流式更新。部署时仅查询125000字节的精确位图，不提取17维特征，不运行模型；缓存命中始终保留。标记跳过消耗原beam槽位，与LR语义相同。

对照：无剪枝DiskANN；io_predictability既有冻结17维state_lr；非学习式Mark。LR使用既有验证标签FPR为0.1%/0.5%/1%选出的3个阈值，保留缓存命中节点。标记支持度和频率阈值只在本轮验证集选择。比较固定相同L和beam，避免改变搜索宽度混淆方法收益。

计时：验证2轮、测试3轮，各轮配置随机顺序串行执行，每个split先做无剪枝完整预热。无audit，标记/模型加载、索引加载和BFS缓存构建排除在查询延迟外；门控查表/特征提取/评分包含在内。报告中位数的平均延迟、p95、QPS，以及确定性的Recall@10、reads/q、expansions/q、skips/q。reads为submitted SSD requests，不等于物理设备读盘。

主要比较：相对同split无剪枝baseline的平均Recall损失预算0/0.1/0.5个百分点，分别选择验证reads最少、验证latency最低配置；每种方法都允许回退无剪枝。若没有正收益的可行项，明确回退。选择锁定后才运行测试。所有16组配置均以冻结参数在测试运行三轮，公开完整曲线；不能用测试重新选参，也不能把测试曲线上较优点当作验证选中的主结果。测试质量约束失败如实报告。

内存：位图存储及在线数组均为125000字节/数据集（1M节点）；离线计数数组n/z合计8MB，运行时不加载。LR报告模型参数字节，不将共享索引和BFS缓存算作方法独有内存。额外报告训练节点覆盖、位图标记数量、测试baseline中命中标记比例（事后诊断，不能用于改标记）。验证空位图与baseline输出/reads完全一致，三轮测试输出确定性，query划分互斥，位图生成规则与事件计数一致。
