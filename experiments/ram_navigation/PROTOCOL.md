# 固定 RAM 预算的静态导航图实验

复用既有 SIFT1M 和 DEEP1M DiskANN Vamana 索引（原图最大度 64），底层搜索固定 L=100、k=10、beam=4、不使用 pruning/ET/reorder。独立 RAM 导航使用 exact L2、64 容量候选队列、最多展开 64 个 RAM 节点，取已经展开的最近 4 个全局节点 ID 交给底层搜索。底层同时插入原 medoid 初始候选，并从驻内存 PQ 编码重新计算种子距离，随后执行原始 best-first。未复制完整 RAM 候选队列或精确结果到 SSD 搜索；原 medoid 候选之后仍可按原 L 队列规则淘汰，不声称强制完成原入口路径。

主比较所有 B2–B5 导航预算均为 64，确保 B3/B4 比较只改变图结构。另外在独立验证查询扫描 16/32/64，报告验证选择的预算作敏感性对照；如果该方法没有平均 Recall 不低于 B1 的验证可行项，保留 64 并明确标记失败，不偷偷回退到另一方法或用测试反馈调参。

## 数据划分与方法

历史反馈来自原有 8,000 条训练查询的 L100 展开记录，验证、测试各 1,000 条 query ID 与历史互斥。虽然原 trace 文件包含全部查询，只对训练 ID 更新频率和代表点。图构建只使用历史频率、历史已展开节点的 exact 距离、底库向量与原图元数据；不使用验证/测试 GT 或反事实标签建图。没有训练神经网络、没有热点迁移、没有在线缓存更新。

- B1：原始 DiskANN + BFS Cache，原 medoid 入口，无独立导航。
- B2：按历史展开频率选热点节点，强制保留 medoid；RAM 图使用这些节点之间的**全部原始连接**，没有逐点 16 边截断。
- B3：70% 节点来自热点，剩余节点用贪心查询覆盖选择。覆盖目标为历史查询到已选缓存向量的最小 squared L2 除以查询范数，加入历史最近展开节点来降低尚未覆盖查询的距离。仍保留全部驻留节点之间的原边。
- B4：节点集合与 B3 完全相同。对选中向量生成 64 个近邻候选与 32 个随机候选，使用 alpha=1.2 的 Vamana 式多样化剪边选 14 条边，再保留双向环的 2 条连接；这是独立几何构图 PoC，不声称等同于原生 Vamana 建图程序。每点 16 条导航边，环保证从 medoid 全图可达。
- B5：从 B4 出发，执行一次静态耦合更新。用历史 RAM 路由访问次数、历史查询最近缓存点责任、原始频率决定移除名单；替换约 5% 节点为历史导航覆盖较差查询的代表点，再重建几何边。重新回放历史 RAM 导航，对源节点到历史最近缓存目标的相对距离收益累积评分，每个源最多替换一条非环边。节点数和全局边槽容量保持不变。它是联合启发式，不是全局最优解；候选展开顺序没有被误当作连续图路径。

B2/B3 以本地 ID 的 CSR 保存全部驻留原连接；B4/B5 用本地 ID 的定长邻接表。各组预留相同的 16N 全局边槽容量，CSR 可保留某个节点最多 64 条原边，不按逐点 16 截断。实际有效边数量不同，但分配的边槽 RAM 相同。CSR 与直接遍历原 Cache 邻接表的实现逐查询计数/Recall 完全一致，避免原边组在线做大量全局缓存成员查询产生计算混淆。

## RAM 预算与所有权

公共上限取 B1 的 10,000 节点缓存实际保留分配。SIFT：9,559,312 bytes（约 9.12 MiB）；DEEP：8,281,360 bytes（约 7.90 MiB）。B2–B5 分别使用相同的 9,000 / 8,850 个节点，以给独立边表和工作区留出空间。四组的节点数、边槽容量、元数据格式与查询工作区容量相同；实际预算上限相同，不要求浪费字节让所有方法恰好填满上限，剩余空间如实报告。

计入的增量 RAM 包括：

1. 原生坐标缓存全部 aligned float32 分配（不是仅计算有效维度的逻辑字节）；原生最大度邻接缓存全部分配；两个查询索引哈希表的实际分配与容器对象。
2. 独立图全局 ID、本地邻接/CSR、度数/偏移、root/layout 等索引元数据；包括预留但未使用的边槽。
3. 四个线程的 RAM 导航 visited 数组、64 容量队列、top-4 和交接种子，以及工作区对象。

导航与原生缓存共享一份向量，向量成本已经计入原生 Cache，而不是声称“向量免费”。原生原邻接表继续完整驻内存供底层搜索使用，独立导航边表的额外空间也计入。热点频率表、历史轨迹、全量原始浮点向量、离线构图候选不驻留查询进程。

预算关系为固定公共 DiskANN 索引/PQ/原生线程工作区 + 受控 Cache/导航上限。公共底层没有新增全量向量或全量浮点搜索索引。使用 TCMalloc current_allocated_bytes 差分与 GetAllocatedSize 计量保留分配，并补计容器对象；记录预热后整进程 live heap 和 max RSS。该预算针对索引、缓存和工作区，不把 allocator 空闲保留页、内核状态或 OS 页缓存假称成图结构字节；RSS 单独报告，不宣称各进程 RSS 恰好相同。

## 测量

导航完全在已驻留数组中执行，不提交 SSD 请求。Submitted SSD Read Requests 来自底层 QueryStats.n_ios，**不是 Physical SSD I/O**；包括所有入口之后的搜索请求。缓存加载、图构建与预热请求单独属于初始化，不混入单查询分母。

端到端延迟包围 RAM 导航与完整底层函数调用，包括入口交接和 PQ 初始化；导航时间独立计时，底层完整阶段用端到端减导航时间计算，不能仅用原生内部 total_us 代替完整底层阶段。QPS 按整批 wall time 计算，包含统一的计分/记录开销。

性能运行固定 4 线程、MKL=1，OMP_PROC_BIND=close、OMP_PLACES=cores；每轮确定性打乱方法顺序，三轮取中位数，并保存各轮数据。32 条固定前缀仅用于预热，不改变静态缓存或训练参数。主比较另保存 cache-only 的 B2/B3/B5 控制，关闭导航但保留同一内存配置；B4 的 cache-only 与 B3 相同节点及原生邻接，因此复用 B3 控制。报告平均 Recall、逐查询下降/改善数与配对 bootstrap；平均不下降不代表每条查询不下降，置信区间覆盖零也不构成质量保证。
