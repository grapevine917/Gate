# P0-C：Gate实现消融

## 选择建议

以Recall–P95为首要目标：当前实现优先LR。6个预声明质量要求下，LR在Gate中有5个最低P95，MLP有1个；98%附近MLP仅略低，不能将微小差异视为显著。该计数是有限网格的描述性结果，不是完整连续前沿的统计检验。

MLP的代理标签AUROC/AP最好，原生推理约0.618μs，保留为更强非线性预测候选。但当前测量不支持仅凭AUROC将其设为低延迟默认。XGBoost预测能力略低于MLP、单候选推理约慢13倍，当前278树实现未显示足够补偿。q–v MLP在本次L100诊断中AUROC更低，推理约3.583μs并额外占用512MB向量内存；不建议作为默认，不能据此否定所有查询交互模型。

Tuned DiskANN仍是必要参考。95%到99.7%的各个质量要求下，它的最低P95均低于所有Gate；90%处LR仅有约0.17%的微小表面差异，不能宣称改善。学习剪枝可以改善读取流量或吞吐，但未显示普遍尾延迟收益。

例如测试Recall≥99.5%：LR实际Recall99.59%，对比Tuned DiskANN99.58%，P95为7.313ms对7.073ms（增加3.39%），同时QPS由603.0增至697.1（+15.60%）、读取量减少15.50%。因此“采用哪个Gate”和“是否采用Gate”是两个需要分别回答的问题。

## 范围与公平性

这是方法实现消融，独立于P0-A固定参数和P0-B原始Gate调参实验。四种Gate使用既有同一组混合L训练样本：1200个训练查询、285754个cache-miss候选。LR/XGBoost/MLP使用同一17维状态；q–v MLP使用[q,v,abs(q-v),q*v,state17]共529维。标签统一为“有新邻居入队或属于本次baseline最终Top10则retain”，是贡献代理标签，不是反事实Recall损害标签。

MLP为17–128–64–1，q–v MLP为529–128–64–1；XGBoost为278棵最大深度5的树；LR为标准化线性逻辑回归。冻结权重，不在本次测试集上重新训练。训练查询与验证/测试互斥，XGB/MLP轮数在训练内部1000/200查询划分上选择后再用1200查询拟合。

P0-C的17D MLP是这组匹配训练的mixed-L权重，不是P0-A/B的原始L100模型。不得将跨实验的MLP差异全部解释为模型实现差异。

## 预测能力与单候选推理成本

下表在同一批102405个测试集L100 baseline缓存未命中候选上评价；所有四种模型的样本与标签完全一致。AUROC以retain为正类，AP以可剪枝代理标签为正类。单候选耗时是原生C++单线程score，20,000个随机样本、预热后5次扫过的平均耗时的中位数，不使用批量推理。包含归一化和q–v特征拼接/向量访问，不含搜索队列状态抽取；真实搜索时间则全部包含。

## 解释边界与复现

查询曾被观察，属于探索性消融；64配置有限网格不证明全局最优。三次计时中位数仍有选择噪声，数个百分点以内的差异不能自动宣称显著。预测诊断限于L100 baseline状态；真实搜索覆盖全部L与Gate干预轨迹。

依次运行prepare.py、predict.py、run.py、verify.py、plot.py、analyze.py、report.py；不能并发运行微基准与搜索计时。已有完整搜索可复用，重新计时先归档runs。原始数据：prediction_metrics.json、prediction/*.bench.json、frontier_points.csv、strict_equal_recall.csv、all_configurations.csv、PROTOCOL.json及INPUT_LOCK.json。
