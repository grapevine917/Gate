# RAM 四入口与底层入口价值诊断

每个数据集使用独立测试集的固定随机 200 条，三种拓扑使用相同查询。固定缓存、RAM budget=64 和底层 k=10/L=100/beam=4；所有四入口试验均保留原始 medoid 候选。Oracle 使用该查询的反事实结果，保证逐查询 Recall 不低于 current4；它是诊断机会空间，选择成本不免费，也不是最优组合证明。详见 [PROTOCOL.md](PROTOCOL.md)。

**结论：当前入口不是最优，但本轮未发现入口排序是主要瓶颈。** 已展开节点内重选四入口仅节省约0.5%请求；扩展缓存候选或纳入底层轨迹/GT反馈后，启发式Oracle约节省1%–1.5%。在固定L=100下，大量剩余成本仍属于底层精细搜索。拓扑影响候选发现，因此不能将入口排序与图结构当作互斥因素，更不能把有限候选的Oracle当作所有入口算法的上界。

## 底层精细搜索的剩余成本

SIFT：无 RAM 入口时底层平均展开 111.850 个节点；当前四入口为 104.120；缓存候选四入口 Oracle 为 103.110。在 L=100 下，即使替换入口，底层仍展开约103个节点并提交约97–99次读取请求。结果指向精细搜索阶段占据大部分剩余成本；不能把 L=100 当成所有算法的理论最少展开数。
DEEP：无 RAM 入口时底层平均展开 112.165 个节点；当前四入口为 104.735；缓存候选四入口 Oracle 为 103.040。在 L=100 下，即使替换入口，底层仍展开约103个节点并提交约97–99次读取请求。结果指向精细搜索阶段占据大部分剩余成本；不能把 L=100 当成所有算法的理论最少展开数。

底层候选包含 current4/no_navigation 实际展开节点、RAM 展开节点和 GT Top-10，并非全图穷举。它和缓存最近32候选池不互相包含，因此不能直接用两个 Oracle 的差当作缓存覆盖缺口。非缓存入口本身的正常底层读取已计入请求；只有离线选择入口的试验成本没有计入每个结果行，另有 diagnostic_cost 记录。

## 如何判断瓶颈

相同缓存节点及固定四入口交接后，三张 RAM 图的底层结果逐查询完全一致。这说明 RAM 拓扑通过“找到并交接哪些入口”影响底层检索；入口选择与拓扑发现不是互斥解释。已展开集合内 Oracle4 的收益检验入口排序；扩大候选池的收益检验发现与覆盖。只有在同一已展开集合内重选取得主要收益时，才有证据把主要瓶颈归于入口排序。当前数据需要同时考虑排序和覆盖，不能直接宣布图结构已不重要。

完整原始候选结果与所选入口 ID 在各数据集 *.candidates.csv / *.entries.csv；summary.json 和 bottom_summary.json 提供统计，verification.json 保存对照检查。本轮200查询诊断不代替完整1000查询的上一轮拓扑评估，也不证明 Oracle 规则能在独立部署查询中实现收益。
